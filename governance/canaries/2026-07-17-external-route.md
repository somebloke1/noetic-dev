# External Route Canary Procedure

This procedure exercises the live external routing path introduced by issue #51. It does not itself claim that an execution has occurred. A PR introducing or changing the protected capture workflow is bootstrap-only and ineligible; acceptance requires a separate subsequent candidate whose protected base already contains the complete workflow, policy, capture, and validator paths.

The authoritative record is the successful protected Agent Review run and its 90-day `agent-review-<pr>-<head-sha>/agent-review-result.json` artifact. Run `/usr/bin/python3 -I scripts/governance/route_evidence.py --run-id <run-id> --pr-number <pr> --head-sha <head-sha>` from a detached checkout of the associated PR's exact `base.sha`, never from the candidate or a moving branch. Isolated Python execution is mandatory. The validator itself queries GitHub for that base SHA and refuses a different `HEAD`, a modified validator, any untracked or ignored file, a replacement object, or a modified policy declaration. It also requires the exact repository, protected workflow path and event, successful run conclusion, same-repository `dev` PR, candidate and protected-base SHAs, and unexpired run-bound artifact. The artifact carries `governance/protected-dev-ruleset.json` from the protected base checkout; an administrator-capable validator requires GitHub's complete applicable-rules response and active, no-bypass ruleset to match that declaration, to have remained unchanged since before the run, and to require the workflow and governance checks. The validator downloads the artifact itself rather than accepting caller-supplied JSON, then checks the wrapper, canonical router component, classification, decisions, one invocation per decision, acknowledged outcomes, and shared immutable `decision_id`. It accepts GitHub's run SHA as either the candidate or protected base while deriving their distinct identities from the associated PR. The router's root-owned `state/decisions.jsonl` and `state/outcomes.jsonl` are corroborating host records retained with the deployed component.

After merge, the recurring operator described in `../../docs/governance/route-attestation.md` replays this validation from a fresh exact-base clone and records a local receipt. The stable PR endpoint, not the workflow run's ephemeral `pull_requests` array, supplies historical candidate/base identity.

Accept one execution only when those records bind the exact candidate request to protected CI, genus-router `route_task`, canonical LiteLLM invocation, and genus-router `report_outcome`. Records from separate executions cannot be combined. Broker-local routing claims and controlled test fixtures do not satisfy the procedure.
