# OpenCode Credential-Isolation Spike

Issue #65 permits one source-free OpenCode turn. This inert slice neither executes it nor establishes readiness or delivery evidence.

## Contract

Policy stays contract-only and not ready. Results are permanently `non-evidence` with no outcome ID. The controller pins OpenCode 1.17.20, genus-router, canonical LiteLLM, and the honest Luna/Terra/Sol trivial route; drift fails closed.

## Isolation

```text
tokenless route -> credential-owning execute parent -> tokenless outcome
```

Only non-login `llm-svc` receives the systemd credential. Root publishes bounded files with no-follow/exclusive opens into immutable `handoff-state`; outcome must match every execution field to that authenticated result. Router logs use classified non-production state.

Bubblewrap exposes no source or host network and gives OpenCode only a dummy loopback relay. The parent accepts one exact request, revalidates the LiteLLM process/socket before authorization, rejects tools/drift/replay, and corroborates one exact-nonce response with three OpenCode events. `steps=2` avoids the version's first-request warning.

## Replay

Claims precede irreversible actions. Execute never retries. Outcome persists `report-issued`; recovery only reconciles one exact isolated log record or fails unresolved. Preserve failed state.

## Operation

After merge and protected gates, installation verifies pinned identities and the existing systemd credential, writes no credential, and starts nothing:

```bash
sudo deploy/install-opencode-spike.sh <source> <commit-sha> <opencode-binary>
```

The root-only orchestrator is a separate one-time invocation. Tests use local fakes; `NOETIC_OPENCODE_TEST_BINARY` adds the pinned binary in network-unshared Bubblewrap.
